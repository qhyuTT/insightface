# Lessons

- 本项目必须使用 `uv` 管理 Python 版本、依赖、虚拟环境、锁文件和命令执行；文档与验证命令统一使用 `uv sync`、`uv run`，不以裸 `pip` 作为主流程。
- InsightFace 1.x 的 Auto 检测会组合 128 与 640 尺度；不能只因 640 适合小脸就固定为 640，否则可能漏掉占据画面大部分区域的近距离人脸。登记照和视频流都应保留双尺度默认值，除非有实测数据支持覆盖。
- 登记照片与实时视频帧不能共用同一个清晰度阈值：登记照可接受稳定的轻微柔焦正脸，视频证据则需要严格过滤运动模糊；应分别配置并通过真实样本回归。
- 实时视觉 PoC 不能只交付 Swagger 和事件 API；操作者需要可视化监控页看到当前输入流、检测框、匹配置信度和搜索状态，否则即使后台持续运行也缺少可观测性。
- 目标登记除了人脸照片还要保留操作者提供的显示姓名；姓名应随搜索事件传递到前端，但不要直接拼入 HTML，避免用户输入造成 XSS。
- 人脸框短边阈值必须以推理原始帧而非浏览器预览尺寸为准。机场 1080P 场景采用分层策略比简单降低阈值更稳妥：`>=80 px` 使用 `0.55 / 3 帧 / 1.5 s`，`64-79 px` 使用 `0.60 / 4 帧 / 2 s` 并抑制候选事件，`<64 px` 拒绝；输入降采样会直接改变人脸所属档位。
- “人脸在人体框上方 60%”是人脸中心与人体轨迹的空间关联规则，不是人脸检测规则。坐姿和截断场景可以在仅有一个完整人体框包含人脸中心时放宽；多人框重叠时不能猜测归属，无人体关联时只能使用短时人脸 IoU 兜底并执行更严格证据策略。
- T4 上的机场 1080P 基线是全帧人脸检测 `10 Hz`，必要时以 `4 Hz` 对最多 `8` 个高置信人体 ROI 补检。优化召回时必须同时观察 P95 延迟、丢帧、人脸尺寸、拒绝原因和关联路径，不能只看画面上是否出现人脸框。
